# infra/

Everything that describes the cluster and what is deployed in it. Folders are filled in phase by phase of the [roadmap](../docs/01-roadmap.md).

| Folder | Contents | Phase |
|---|---|---|
| `cluster/` ✅ | kind config (`kind-config.yaml`: 1 control-plane + 2 workers, ports 80/443 bound only to 127.0.0.1, registry mirrors for containerd) | 0, 5 |
| `manifests/platform/` ✅ | What belongs to the platform rather than to an application: namespaces with Pod Security (`sandbox`, `sre-agent` — restricted and in the mesh; `monitoring` — privileged), CA issuers, default-deny NetworkPolicy, Linkerd identity (cert-manager). One file per namespace (`namespace-sandbox/monitoring/sre-agent/chaos-mesh.yaml`). Raw application manifests from Phases 1–2 were replaced by the chart (they remain in git history: `8a47ee6`, `95f2f88`) | 1–5 |
| `helm/sandbox-service/` ✅ | Our chart for the .NET services and the agent: Deployment, Service, Ingress, ServiceAccount, NetworkPolicy, HTTPRoute (retries/timeouts), PodMonitor, SLO rules | 3, 5, 6 |
| `helm/postgres/` ✅ | Our PostgreSQL chart: StatefulSet, headless Service, PVC, postgres-exporter, `PostgresDown` | 4, 5 |
| `helm/loadgen/` ✅ | Background load with k6 through Traefik | 5 |
| `helm/sandbox-observability/` ✅ | Grafana dashboards as code (`dashboards/*.json`) | 5 |
| `helm/releases/<namespace>/` ✅ | Values of a separate release for each component; the folder name is the namespace | 3–5 |
| `helm/values/` ✅ | Values for community charts: traefik, cert-manager, kube-prometheus-stack, loki, alloy, linkerd (crds, cni, control-plane, viz); chaos-mesh later | 2+ |
| `manual/` | Optional "manual mode" of Phase 1: the same bare manifests for `kubectl apply` in a **separate** namespace `sandbox-manual` (images 0.1.0, no Helm/mesh/DB). The project's working deployment is Helm only; this folder does not interfere with it, see [manual/README.md](manual/README.md) | 1 |
| `chaos/` | Chaos Mesh experiment manifests (always limited to the `sandbox` namespace) | 9 |

Rules:
- in manifests and values, short comments explain "why", not "what";
- secrets are not committed in plain text (they are generated by scripts; Sealed Secrets later);
- versions of community charts are pinned explicitly.
