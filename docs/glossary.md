# Глоссарий

## SRE и надёжность

| Термин | Объяснение |
|---|---|
| **SRE** | Site Reliability Engineering — подход Google: эксплуатация как инженерная задача, надёжность измеряется и управляется через SLO |
| **SLI** | Service Level Indicator — измеримый показатель качества (доля успешных быстрых запросов) |
| **SLO** | Service Level Objective — целевое значение SLI (99% за 30 дней) |
| **SLA** | Service Level Agreement — договорное обязательство перед клиентом, обычно мягче SLO |
| **Error budget** | Допустимая «ненадёжность»: 100% − SLO |
| **Burn rate** | Скорость расходования error budget; основа зрелых алертов |
| **Golden signals** | Latency, traffic, errors, saturation — 4 базовых сигнала сервиса |
| **MTTR / MTTD** | Mean time to recovery / detection — среднее время восстановления / обнаружения |
| **Toil** | Ручная повторяющаяся операционная работа, которую стоит автоматизировать |
| **Runbook** | Инструкция «что делать при таком-то алерте» |
| **Postmortem** | Разбор инцидента; blameless — без поиска виноватых, с поиском системных причин |
| **On-call** | Дежурство; человек, который реагирует на алерты |
| **Escalation** | Передача проблемы человеку (или следующему уровню), когда автоматика не справилась |

## Kubernetes

| Термин | Объяснение |
|---|---|
| **kind** | Kubernetes in Docker — кластер, где «ноды» — это Docker-контейнеры |
| **Control plane** | Управляющая часть кластера: apiserver, etcd, scheduler, controller-manager |
| **kubelet** | Агент на ноде, запускающий контейнеры подов |
| **Pod** | Минимальная единица запуска, один или несколько контейнеров |
| **Deployment / ReplicaSet** | Управление N одинаковыми подами и их обновлениями |
| **StatefulSet** | Поды со стабильной идентичностью и собственными томами (для БД) |
| **DaemonSet** | По одному поду на каждой ноде (сборщики логов, node-exporter) |
| **Job / CronJob** | Разовая / периодическая задача |
| **Service** | Стабильное имя и балансировка для группы подов |
| **Ingress / Ingress Controller** | Правила HTTP-маршрутизации извне / прокси, который их исполняет |
| **Gateway API** | Более новая и выразительная замена Ingress |
| **ConfigMap / Secret** | Конфигурация / чувствительная конфигурация (Secret = base64, не шифрование) |
| **PV / PVC / StorageClass** | Том / заявка на том / тип хранилища с автосозданием |
| **Namespace** | Логическое разделение ресурсов кластера |
| **Label / Selector** | Метки на объектах / выборка по меткам (так Service находит поды) |
| **Annotation** | Метаданные для инструментов (не для выборки) |
| **Probe** | Проверка liveness/readiness/startup контейнера |
| **Requests / Limits** | Гарантированные / максимальные ресурсы контейнера |
| **OOMKilled** | Контейнер убит за превышение лимита памяти |
| **CrashLoopBackOff** | Контейнер постоянно падает, k8s перезапускает с растущей паузой |
| **RBAC** | Role-Based Access Control: ServiceAccount, Role, RoleBinding |
| **NetworkPolicy** | Правила сетевого доступа между подами |
| **CNI** | Плагин сети кластера (kindnet, Calico, Cilium) |
| **CRD** | Custom Resource Definition — собственный тип объекта в k8s |
| **Operator / Controller** | Программа, приводящая фактическое состояние к желаемому (reconcile loop) |
| **Reconcile loop** | Цикл «сравнить желаемое и фактическое → сделать шаг» |
| **Helm / Chart / Release / Values** | Пакетный менеджер / пакет / установленный экземпляр / параметры |
| **GitOps / Argo CD** | Кластер синхронизируется с состоянием в git |

## Сеть и безопасность

| Термин | Объяснение |
|---|---|
| **TLS** | Шифрование канала, клиент проверяет сервер |
| **mTLS** | Взаимный TLS: обе стороны проверяют сертификаты друг друга |
| **cert-manager** | Оператор выпуска и продления сертификатов в k8s |
| **Service mesh** | Слой прокси рядом с каждым сервисом: mTLS, метрики, retries, маршрутизация |
| **Sidecar** | Дополнительный контейнер в поде (например, прокси mesh) |
| **Linkerd / Istio** | Service mesh: простой и лёгкий / мощный и сложный |
| **Zero trust** | Не доверять трафику только потому, что он «внутри сети» |
| **Blast radius** | Масштаб возможного ущерба от действия или сбоя |

## Observability

| Термин | Объяснение |
|---|---|
| **Prometheus** | Система сбора и хранения метрик (pull-модель) |
| **Scrape** | Опрос `/metrics` сервиса Prometheus'ом |
| **PromQL / LogQL** | Языки запросов Prometheus / Loki |
| **ServiceMonitor** | CRD: «скрейпить такие-то сервисы» |
| **Exporter** | Программа, отдающая метрики чего-либо в формате Prometheus |
| **Alertmanager** | Маршрутизация, группировка, подавление алертов |
| **Loki** | Хранилище логов с индексом по labels |
| **Grafana** | Визуализация метрик и логов |
| **OpenTelemetry (OTel)** | Стандарт и SDK для метрик, логов и трейсов |
| **Trace / Span** | Путь запроса через сервисы / один его участок |
| **Cardinality** | Число уникальных комбинаций labels; высокая — убивает Prometheus |

## AI-агенты

| Термин | Объяснение |
|---|---|
| **LLM** | Large Language Model |
| **Agent harness** | Код вокруг LLM: триггеры, контекст, tools, цикл, лимиты, журнал |
| **Tool / function calling** | Механизм, когда модель запрашивает вызов функции со структурированными аргументами |
| **ReAct** | Паттерн «рассуждение → действие → наблюдение → …» |
| **Ralph loop** | Внешний цикл агента: та же задача снова и снова, каждый раз со свежим контекстом, пока код не подтвердит, что задача решена (или не кончатся лимиты) |
| **RALF** | Одна итерация Ralph loop в этом проекте: Retrieve → Analyze → Lead → Feedback |
| **RunState** | Файл прогресса между итерациями Ralph loop — память агента вне контекста модели |
| **Completion check** | Детерминированная проверка «задача решена», не зависящая от мнения модели |
| **OODA loop** | Observe–Orient–Decide–Act — военная модель принятия решений, близкая по духу |
| **Context window** | Максимальный объём текста (в токенах), который модель видит за раз |
| **Token** | Единица текста для модели (≈ 3–4 символа англ. текста) |
| **Guardrails** | Детерминированные ограничения на то, что агент может сделать |
| **Human-in-the-loop** | Человек подтверждает действия агента |
| **Prompt injection** | Атака: инструкции для модели спрятаны в данных (например, в логах) |
| **Evals** | Набор сценариев с ожидаемыми результатами для оценки качества агента |
| **OpenAI-compatible API** | Протокол `/v1/chat/completions`, который поддерживают многие провайдеры и LM Studio |
| **LM Studio** | Приложение для запуска LLM локально с OpenAI-совместимым сервером |
| **Microsoft.Extensions.AI** | .NET-абстракции (`IChatClient`) над разными LLM-провайдерами |
