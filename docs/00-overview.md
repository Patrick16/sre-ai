# 00. Обзор проекта

## Зачем этот проект

Это учебная песочница. У проекта три цели, по возрастанию «интересности»:

1. **Kubernetes «как на проде».** Поднять локальный кластер и настроить в нём всё,
   что обычно встречается в реальном продакшене: Deployments, Services, Ingress,
   ConfigMaps, Secrets, Helm, постоянное хранилище, NetworkPolicy, mTLS,
   service mesh. И главное — понимать, *зачем* нужна каждая вещь.
2. **SRE-окружение.** Настроить мониторинг (метрики, логи, алерты, дашборды),
   научиться формулировать SLI/SLO, ломать систему контролируемо (chaos engineering)
   и видеть, как это отражается в телеметрии.
3. **AI-агент для SRE.** Спроектировать и написать на .NET собственный agent harness:
   агент сам собирает состояние системы, рассуждает о нём через LLM, выполняет
   только безопасные действия и пишет отчёт.

## Что считаем успехом

- Кластер поднимается одной командой из `scripts/` и разворачивается Helm-чартами.
- В Grafana видны метрики и логи всех сервисов, Alertmanager шлёт алерты.
- Трафик между сервисами идёт через mTLS (service mesh), есть Ingress снаружи.
- Хаос-эксперимент (например, убить под или добавить задержку сети) приводит к
  алерту, агент его замечает, диагностирует, выполняет безопасное действие
  (или предлагает его) и пишет отчёт (на PVC агента, `GET /runs/{id}/report`; game day — в `.local/game-day/`).
- Владелец проекта может объяснить своими словами каждый компонент.

## Что в scope, а что нет

| В scope | Не в scope |
|---|---|
| Локальный кластер (kind/minikube) | Облачные managed-кластеры (EKS/AKS/GKE) — можно позже как бонус |
| Простейшие sandbox-сервисы на .NET | Реальная бизнес-логика |
| Агент с allowlist безопасных действий | Агент с произвольным доступом к кластеру |
| LLM через OpenAI-совместимый API / LM Studio | Обучение/дообучение собственных моделей |
| Chaos engineering внутри песочницы | Хаос на чём-либо, кроме локального кластера |

## Стек

| Слой | Технология | Почему |
|---|---|---|
| Кластер | kind (Kubernetes in Docker) | Мультинодовый кластер локально, быстро пересоздаётся |
| Пакетирование | Helm | Стандарт де-факто для деплоя в k8s |
| Ingress | Traefik | Поддерживает и Ingress, и Gateway API; ingress-nginx закрыт в марте 2026 |
| Сертификаты | cert-manager | Автоматический выпуск TLS-сертификатов, как в проде |
| Service mesh | Linkerd (основной вариант) | Проще Istio, mTLS «из коробки» — идеален для обучения |
| Метрики | Prometheus + kube-prometheus-stack | Стандарт мониторинга в k8s |
| Логи | Loki + Promtail/Alloy | Хорошо интегрируется с Grafana |
| Дашборды | Grafana | Единая точка просмотра метрик и логов |
| Алерты | Alertmanager | Маршрутизация алертов, вебхук в агента |
| Хаос | Chaos Mesh + свои утилиты на .NET | k8s-native эксперименты + понимание «изнутри» |
| Агент и сервисы | .NET 9/10, C# | Требование проекта |
| LLM | OpenAI-совместимый API / LM Studio | Можно работать и в облаке, и полностью офлайн |

Конкретные версии фиксируются в фазе, где компонент впервые ставится (см. роадмап).
